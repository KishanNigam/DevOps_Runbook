Run locally

From the project folder, create a virtual environment, install Flask, and start the local server:

py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python app.py

Open http://127.0.0.1:5000/ in your browser. Stop the server with Ctrl+C. If PowerShell blocks activation, run .\.venv\Scripts\python.exe -m pip install -r requirements.txt and then .\.venv\Scripts\python.exe app.py.

Data and workflow

Runbook files and schema

Runbook JSON files are stored in data/runbooks/ relative to the project folder. Each filename is <id>.json; the ID must match its filename and use lowercase letters, digits, and hyphens.

Each record includes an ID, title, category, technologies, environment, severity, symptoms and errors, root-cause status/details, prerequisites, investigation and resolution steps, verification, rollback, prevention, tags, and timezone-aware creation/update timestamps. Step objects can include a description, display-only command, expected result, and notes. See the schema summary above and the complete schema in README.md under the heading Schema.

Use the form to create or edit records; the app validates required fields and previews the JSON before saving. Browse All Runbooks or Categories and Technologies.

Source control

Git workflow

Replace <repository-url> with the URL for your own repository. Do not put passwords, access tokens, or other secrets in commands or runbook files.

  1. Clone:
    git clone <repository-url>
Set-Location <repository-folder>
  2. Pull updates:
    git status
git pull
  3. Review changes before staging:
    git status
git diff
git diff -- data/runbooks
  4. Commit reviewed work:
    git add README.md app.py templates static tests data/runbooks
git diff --cached
git commit -m "Describe the runbook changes"
  5. Push your branch:
    git push

Git sync only applies to files intentionally tracked in a Git repository. This app does not synchronize local records by itself. Confirm that the repository and its sharing policy are appropriate before tracking operational notes.

Recovery

Back up and restore runbooks

Run these PowerShell commands from the project folder. The backup is written outside data/runbooks/; choose a protected location with enough space.

Create a timestamped backup

$backup = ".\backup\runbooks-$(Get-Date -Format yyyyMMdd-HHmmss)"
New-Item -ItemType Directory -Path $backup -Force
Copy-Item -Path .\data\runbooks\*.json -Destination $backup

Restore from a backup

Copy-Item -Path .\backup\runbooks-YYYYMMDD-HHMMSS\*.json `
  -Destination .\data\runbooks\ -Force

Before restoring, stop the app and back up the current directory. Verify the chosen backup folder and JSON files first; the restore command overwrites files with matching names. Reload the app and check the runbook list afterward. The app has no built-in bulk import, export, delete, or restore operation.

Troubleshooting

Common issues

Flask is not installed
Activate the project virtual environment and run python -m pip install -r requirements.txt. Confirm Flask remains pinned in requirements.txt.
Port 5000 is occupied
Stop the other local process using the port, then retry python app.py. The development server binds to 127.0.0.1.
Malformed JSON
Use the API error message to identify the invalid record, validate its JSON syntax and required schema fields, then restore a known-good backup if needed. Keep a copy before manual repair.
Git reports a conflict
Run git status, inspect each conflicted file, resolve the markers without discarding either needed change, then stage and commit the resolution. For JSON conflicts, validate the final JSON before restarting the app.
A save fails
Keep the form open; validation and API failures leave entered fields in place. Check that data/runbooks/ is writable, the record is valid, and the ID is not already in use. Failed updates preserve the previous JSON file.

For project setup and the full JSON/API documentation, see the dashboard Help section and the README.md in the project root.
